Tačke sprovođenja politike u MySQL 8.4

Jedan kriterijum, tri mesta, četrnaest mehanizama raspoređenih po njima.

Kriterijum Jezgro je jedino koje čita stanje. Plugin i komponenta sude isključivo o vrednostima koje im jezgro preda. Kriterijum govori o potrebnom stanju, ne o trenutku odluke.

Tri mesta

plugin„da li si ti taj" — kredencijal naspram authentication_string, vraća jedan bit, radi samo pri prijavi, bez pamćenja
komponenta„da li je ova vrednost prihvatljiva" — sud nad prosleđenim podatkom, pri CREATE USER / ALTER USER / SET PASSWORD
jezgrosve što zahteva stanje: kolone reda naloga, brojači, mysql.password_history, izbor reda, izbor plugina

Faza 1, redom

1. jezgrosortira mysql.user, bira tačno jedan red
2. jezgročita kolonu plugin izabranog reda
3. pluginprovera kredencijala
4. jezgroaccount_locked („credentials first, then account locking state")
5. jezgroREQUIRE (ssl_type), zatim istek lozinke po uspešnom povezivanju

Sortiranje hostova — od najužeg ka najširem

192.168.1.7literalni IP ili ime hosta
192.168.1.0/24CIDR
192.168.1.0/255.255.255.0mrežna maska
%bilo koji host
''bilo koji host, sortira iza %

Isti host → neanonimni pre anonimnih. Prvi poklopljeni red se koristi, povratka na širi red nema.

Zamka koja bi bila greška u radu Izbor reda u Fazi 1 određuje autentifikaciju i globalne privilegije. Privilegije nad bazom i tabelom traže se nezavisno, u mysql.db i mysql.tables_priv, gde se Host poredi sa hostom klijenta i sme da sadrži % i _. Zato grant dat nalogu 'u'@'%' važi i za sesiju čiji je CURRENT_USER() jednak 'u'@'localhost'. Izmereno na 8.4.11.
jedan red iz Faze 1plugin, lozinka, REQUIRE, zaključanost, globalne privilegije
sopstveno poklapanje u Fazi 2privilegije nad bazom / tabelom / kolonom
CURRENT_USER()imenuje samo red iz Faze 1 — ne prikazuje domet sesije

OR-kompozicija nivoa je zasebno pravilo Faze 2 (kartica 02).

Sintaksa po porodicama

Lozinka

INSTALL COMPONENT 'file://component_validate_password';
SHOW VARIABLES LIKE 'validate_password%';
-- Podrazumevano (8.4.11): policy MEDIUM, length 8, mixed_case 1,
-- number 1, special_char 1, check_user_name ON, dictionary_file prazno,
-- changed_characters_percentage 0.
-- policy je prekidac: LOW = samo duzina, MEDIUM = + sastav, STRONG = + recnik.

SET GLOBAL default_password_lifetime = 90;
ALTER USER 'u'@'localhost' PASSWORD EXPIRE INTERVAL 90 DAY;
ALTER USER 'u'@'localhost' PASSWORD HISTORY 5
  PASSWORD REUSE INTERVAL 365 DAY;

ALTER USER 'u'@'localhost' IDENTIFIED BY 'Nova!2345'
  RETAIN CURRENT PASSWORD;
ALTER USER 'u'@'localhost' DISCARD OLD PASSWORD;

CREATE USER 'u2'@'localhost' IDENTIFIED BY RANDOM PASSWORD;

Nalog

ALTER USER 'u'@'localhost'
  FAILED_LOGIN_ATTEMPTS 3 PASSWORD_LOCK_TIME 1;
-- Politika se cuva kao JSON na samom nalogu:
--   mysql.user.User_attributes -> $.Password_locking
--   {"failed_login_attempts": 3, "password_lock_time_days": 1}
ALTER USER 'u'@'localhost' ACCOUNT LOCK;
ALTER USER 'u'@'localhost' ACCOUNT UNLOCK;

ALTER USER 'u'@'localhost' WITH
  MAX_QUERIES_PER_HOUR 1000 MAX_USER_CONNECTIONS 5;
FLUSH USER_RESOURCES;

Veza

ALTER USER 'u'@'localhost' REQUIRE SSL;
ALTER USER 'u'@'localhost' REQUIRE X509;
ALTER USER 'u'@'localhost'
  REQUIRE SUBJECT '/CN=klijent' AND ISSUER '/CN=ca';
-- skip_networking=ON u my.ini iskljucuje TCP/IP potpuno.
