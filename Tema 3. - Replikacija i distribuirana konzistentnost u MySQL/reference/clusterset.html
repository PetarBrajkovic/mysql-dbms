InnoDB ClusterSet: grupa unutra, asinhrono između

Sažetak lekcije 06. MySQL 8.4.11 i MySQL Shell 8.4.10, naša topologija 3307/3308/3309.

Zašto ne jedna grupa preko regiona

fizika~200 km/ms u vlaknu; 1000 km → najmanje 10 ms RTT (donja granica)
svako komitovanječeka najbližeg člana koji sa primarnim čini većinu; dogovor o redosledu se čeka, primena ne
izbacivanje5 s tišine → sumnja; + group_replication_member_expel_timeout (podrazumevano 5 s u 8.4) → član izbačen, i kad je ispravan. Vrednost je izbor projektanata
refman„designed to be deployed in a cluster environment where server instances are very close to each other“ (§ Requirements)

Arhitektura

sastavprimarni klaster + replika-klasteri; svaki je InnoDB Cluster (grupa); klaster sme da ima i jednog člana
kanalclusterset_replication, asinhron; na članu replika-klastera radi uz group_replication_applier
upisisamo primarni čvor primarnog klastera; replika-klasteri super_read_only = 1 → ERROR 1290. Sukob između regiona se sprečava, ne rešava
OK pokrivavećinu primarnog klastera; ono što je u asinhronom kanalu je prozor gubitka između klastera
izvorMySQL Shell manual, ne refman (memo 07 ga je zato promašio)

Prelazi uloga (izmereno, dva pokretanja)

setPrimaryCluster()switchover: zaključa stari, novi sustigne, zamena; 539 / 444 ms (danas), 478 / 398 ms (tiket 11); ništa izgubljeno
pre operaterapreživeli klaster super_read_only = 1, upis odbijen, UNAVAILABLE; sam se ne unapređuje
forcePrimaryCluster()prinudni failover: 21 617 ms (danas), 23 064 ms (tiket 11); stari klaster INVALIDATED; „may be lost“, „split-brain can happen“
ograđivanjefenceAllTraffic() / fenceWrites() na starom klasteru, ako je možda živ
popravkarebootClusterFromCompleteOutage → rejoinCluster → setPrimaryCluster nazad → rejoinInstance za preostale članove
manual„There is no guarantee that data will be preserved in the event of an emergency failover.“

između klasterareplika-klaster sme da preuzme upise → dostupnost; „InnoDB ClusterSet prioritizes availability over data consistency in order to maximize disaster tolerance“ (Shell manual)
