# Figure pipeline

Shared by every topic. Read this when building a figure. A topic's own `figures/README.md` holds its
naming convention, its per-chapter budget, and the inventory of dedicated scripts it has written.

Figures are generated by the agent end to end — never hand-captured. Hand-capturing does not scale
across ~13 figures and nine sessions, and a screenshot cannot be re-measured when the data changes.

## The three generic paths

- **Plan-shape and tree figures** -> `tools/make-figure.ps1`. Runs the query as
  `EXPLAIN ANALYZE FORMAT=JSON` against the live server (credentials from the topic's own
  `mysql-credentials.cnf`, gitignored), renders it with [`myflames`](https://github.com/vgrippa/myflames)
  (`--type flamegraph` for plan shape, `--type tree` where the tree text is the point, `--type diagram`
  for join order), and rasterizes the SVG to PNG through headless Edge. Also prints `myflames advise`'s
  plain-English read of the plan, useful to talk through live.
- **Result grids**, when the data itself is the point rather than a plan -> `tools/make-table-figure.ps1`.
  No plan to visualize, so it skips myflames: `mysql --html`, wrapped in a minimal light page,
  rasterized the same way. PNG only, no SVG twin.
- **Non-SQL diagrams** (architecture, conceptual comparisons): search first for a suitable
  official/existing diagram (a vendor manual, a citable paper) to reuse, fetched verbatim — no
  re-drawing, no relabeling — and cited by name and link. Fall back to an original diagram only if
  nothing suitable turns up.

These scripts are **run from inside a topic folder**; they treat the current directory as the topic
and write straight into its `figures/` under its naming convention, with nothing to rename by hand.

```powershell
# from inside the topic folder
..\tools\make-figure.ps1 -SqlFile examples\04-explain\01-visual-explain.sql `
    -Database obrada_upita -OutBase figures\04-explain-01-visual-explain -Type flamegraph `
    -Title "SELECT ... WHERE country_code = 'US'"

..\tools\make-table-figure.ps1 -SqlFile examples\04-explain\03-country-code-skew.sql `
    -Database obrada_upita -OutBase figures\04-explain-03-country-code-skew
```

## When to write a dedicated script instead

`make-figure.ps1` assumes one bare query per file and draws one plan. Write a topic-local
`tools/make-lessonNN-<what>.ps1` when the figure is:

- a **before/after pair** needing a session-scoped `SET` in the *same* connection as the measurement;
- a **comparison across many separate plans** rather than one plan's shape;
- an **estimate-against-measurement** comparison, which is about two sets of numbers rather than a shape;
- **text or cross-session** material — a trace, rejected plans, another session's plan — that has no
  shape to draw at all.

Build all of one chapter's figures in a single script sharing one palette, one SVG helper and one
rasterization step, rather than triplicating them.

## Make the script assert its own claim

The pattern that has paid off most: **a figure script declares what the live server must produce and
throws if it does not**, so a stale query breaks the build instead of silently rendering a wrong figure.

Start with single values (this row must produce access type `ref`), then extend to **the whole
argument the figure makes** — including the negative assertions, which are often the load-bearing
ones: throw if a divergence collapses, if a plan that must never be costed *starts* being costed, if
an alternative stops beating the chosen plan. The test is the claim, not just one number in it.

Also assert cleanup: if the script builds statistics or changes server state to make its point, it
should verify the server is back to its original state before finishing.

## Capture standard

- **Light** theme, `--colors hot` for flame graphs (myflames default) — prints cleanly on a white page.
- No window chrome, menus or taskbar — the scripts rasterize the SVG/table directly, so nothing else
  is in frame by construction.
- Target width ~1200-1800px, native PNG (no JPEG artifacts on text). `make-figure.ps1` reads the SVG's
  own intrinsic size rather than a fixed crop, since flame-graph height varies with plan depth.

## Captions and sourcing

`Slika N.N: <opis>`, hand-typed — pandoc does not number them. **No source note** for the author's own
generated figures or original diagrams; authorship is implicit and constant. A source note **is**
required, as an IEEE numbered citation in the caption text (`Slika N.N: ... [k]`), whenever a figure
is a reused official or external diagram — add that source to `references.bib` like any other. Tools
such as `myflames` are cited once in the paper's methodology section, not per figure.

## Reproducibility

Every data-driven figure's script lives in `examples/`, its filename mirroring the figure's filename,
with a one-line comment at the top naming the figure it produces. Non-SQL diagrams are exempt — there
is nothing to run behind them.

Plan-shape figures get an `.svg` twin beside the `.png` (same base name, committed): the myflames
output is the precise source the PNG was rasterized from. Raw `EXPLAIN ANALYZE FORMAT=JSON` plans and
myflames sidecars go to `figures/raw/` and are gitignored — timings are run-specific and not worth
freezing. A figure is regenerated from its `examples/` script, never diffed against an old capture.

**Regenerating a figure re-measures it.** Every run-dependent number in it moves. After any rebuild,
grep `rad.md` for the absolute numbers that figure prints — see `WRITING.md`, "Numbers in prose".

## One-time setup

`pip install myflames`; the database `bin/` directory and the pip user-scripts directory on `PATH`;
the password filled into the topic's own `mysql-credentials.cnf` (gitignored).

## Traps these scripts have already hit

Collected so a later script does not re-learn them.

**PowerShell**

- **Variable names are case-insensitive.** `${SS}` in an uppercase heading silently resolved to the
  lowercase `$ss` helper and rendered `šTA EXPLAIN POKAžE`. Uppercase text needs its own variables.
  A name differing only in casing is the same variable, and PowerShell will not warn.
- **`č` (U+010D) and `ć` (U+0107) are different letters.** The ASCII-only `[char]` helper style makes
  it easy to reach for whichever is already defined; that produced "veču" for "veću". Define both.
- **`$args` is an automatic variable.** Assigning to it produced a `Start-Process` client that never
  connected. Name it `$mysqlArgs`.
- **`Start-Process -ArgumentList` splits on spaces**, unlike the `&` call operator used elsewhere in
  these scripts, so a path containing spaces (these folders all have them) needs embedded quotes.
- **`2>&1` on a native command throws** under `$ErrorActionPreference = 'Stop'`. A helper that
  deliberately captures a tool's `ERROR` lines has to relax the preference around the call.

**MySQL**

- A plain sentinel `SELECT` used to split a script's output **is itself traced**, and with
  `optimizer_trace_limit = 1` it overwrites the trace you came for. Turn tracing off before reading.

**Text in figures has no automated guard.** The self-verifying assertions check numbers against the
live server; they cannot catch a misspelled Serbian heading. **Read the rendered PNG once** before a
figure goes into `rad.md`, the same way the prose gets a `serbian-grammar` pass.
